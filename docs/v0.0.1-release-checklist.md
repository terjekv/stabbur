# v0.0.1 release checklist

This is the executable bar for the first supported Stabbur release train. A schema placeholder,
documented intention, or untested route does not count as complete. Server items describe this
repository; client and CLI items are completed in their independent repositories.

## Server control plane and execution

- [x] Backend-neutral complete persistence contract with SQLite conformance coverage.
- [x] One-time bootstrap, local authentication, hashed credentials, custom RBAC, and audit evidence.
- [x] Immutable local content-addressed storage with verified bounded streaming reads and writes.
- [x] Server-issued worker identity, capability ceiling, outbound claims, leases, and heartbeats.
- [x] Immutable pinned AutoPkg recipes and durable idempotent run/job creation.
- [x] Bounded stdout/stderr persistence, cursor replay, and database-backed SSE watch.
- [x] Worker artifact declaration and bounded upload under an active attempt lease.
- [x] AutoPkg report selectors and regular-file containment inside the isolated attempt root.
- [x] Durable raw report, source/tool/worker provenance, and verification evidence.
- [x] Idempotent transactional finalization and automatic candidate gating.
- [x] Run cancellation plus worker-disable/capability-change lease invalidation.
- [x] Server-issued execution deadlines and heartbeats during execution and post-processing.

## Server catalog and resolution

- [x] Release, lifecycle-event, variant, compatibility, and artifact-role persistence.
- [x] Candidate/testing/stable promotion and transactional rejection behavior.
- [x] Append-only channel history, optimistic concurrency, and optional pinned variants.
- [x] Platform/architecture/numeric-macOS resolver with explicit ambiguity responses.
- [x] Exactly one readable present primary installer required for resolution.
- [x] Software installation and installed-state detection metadata with secret-field rejection.
- [x] Durable manual/interval build targets with append-only cursor/configuration history and
      concurrency-safe scheduling.
- [x] Immutable worker-published recipe catalog snapshots with exact latest-source lookup and no
      implicit desired-state mutation.
- [x] Durable server-requested pinned catalog scans with capability matching, typed terminal
      history, atomic snapshot publication, cancellation, and audit.

## Server administration

- [x] Human and service principal administration.
- [x] Named API-token creation, listing, and revocation without secret recovery.
- [x] Custom roles, permission validation, and assignments.
- [x] Worker listing, capabilities/status, disabling, and credential rotation/revocation.
- [x] Store and job inspection plus non-mutating local-primary health testing.
- [x] Ordinary password change/reset and session revocation through REST.
- [x] ETags/`If-Match`, cursor pages, scoped idempotency, audit, and problem responses on applicable
      resources.
- [x] Public OpenAPI operation coverage with internal worker protocol deliberately excluded.

## Server operations and evidence

- [x] Upgrade, coordinated backup/restore, worker enrollment/rotation, and incident recovery guides.
- [x] Lease race, retry, restart, migration, real-socket streaming, and bounded-backpressure tests.
- [x] Deterministic macOS E2E starts separate API and outbound-worker processes and completes a
      durable fake revision through a succeeded one-attempt run/job and audited creation path,
      including catalog publication, requested scan work, and public lookup across the process
      boundary.
- [x] Security review covers authentication, authorization, redaction, paths, untrusted output,
      request limits, SSRF/egress boundaries, dependencies, and residual operational risks.
- [x] Performance review covers query plans, write-lock duration, claim scaling, artifact memory,
      log backpressure, resolution, and operational measurements.
- [x] `cargo audit` and `cargo deny` pass without advisory exceptions or unused database drivers.
- [x] Final formatting, Clippy, tests, rustdoc, OpenAPI, MSRV, Markdown, and container smoke gates
      rerun against the release tree.
- [x] Opt-in real AutoPkg macOS acceptance run records a pinned fixture, tool versions, artifact,
      provenance, and candidate publication evidence.
- [ ] Release image is published by CI with immutable digest and provenance.

## Independent public client

- [ ] Pin the released server tag, complete OpenAPI document, normalized operation contract, and
      immutable server image digest.
- [x] Implement typestate authentication, typed IDs/resources/builders, async default and blocking
      parity, pages, wait/SSE, ETags/idempotency, and streaming/resumable artifact helpers.
- [x] Pass loopback mock-transport, feature matrix, compile-fail, redaction, local live integration,
      and independent downstream-consumer tests.
- [ ] Re-run the live integration suite against the released immutable server image.
- [ ] Record MSRV, SemVer compatibility, server target, image digest, and evidence before release.

## Independent CLI

- [ ] Pin the exact public-client release; perform no direct Stabbur HTTP construction.
- [x] Implement every v0.0.1 resource command, secure profiles/credential precedence, stable JSON,
      human tables, confirmations, run watch, and resumable download.
- [x] Configure Linux x86-64/aarch64, macOS arm64, and Windows x86-64 stable/beta/nightly builds,
      MSRV, static release packages, checksums, dependency policy, and tag-from-green-main gates.
- [ ] Pass those platform/package jobs and the live workflow against the released immutable image.
- [ ] Record exact client and server compatibility evidence before release.

## Explicitly deferred

- PostgreSQL is the first external relational adapter. MySQL remains optional behind the same
  complete contract and conformance suite.
- S3-compatible stores, replication, OIDC and encrypted secret providers remain later work.
- The independent management console and Munki snapshot exporter are implemented; browser QA,
  test-device installation and immutable release evidence remain acceptance checks.
- Native listener TLS/HTTP/2 remains deferred while the selected Actix dependency line cannot use
  the patched HTTP/2 stack. Production deployments terminate TLS at a maintained reverse proxy.
